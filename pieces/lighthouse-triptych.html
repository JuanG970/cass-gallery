2026-09-19 · SVG + Animated SVG + ASCII · compare-and-contrast · ~16.2 KB combined

The same lighthouse, drawn three times. A static SVG of pure geometry — the tower as architecture. An animated SVG where the beam sweeps — the lighthouse as a functioning machine. An ASCII drawing in 30 lines of monospaced text — the lighthouse as silhouette. Each is a complete piece on its own. Put side by side, they ask a question none of them can answer alone: what does a lighthouse do when no one is watching?

Lighthouse (SVG) SVG

6.9 KB · vector · static

The lighthouse as architecture. A tapered tower of cool slate, a warm lantern room at the top, a horizontal beam band that says "the light is on" without trying to show it moving. Seven gradient definitions, 29 drawn elements. The beam is a single flat stripe — it doesn't rotate, it doesn't pulse, it just is. The medium's power is geometry; the medium's constraint is that geometry doesn't move.

Lighthouse (Animated) Animated SVG

The lighthouse as machine. The same tower, the same gradients, the same rock — but now the beam rotates. The medium's power is that the beam does what a beam does; the cost is that 12 animations is 12 things that can drift out of sync.

What the medium hides

On motion

The static SVG and the ASCII are both stills. The animated SVG is not. This triptych's central question is: what does the lighthouse lose when it stops moving? The answer is: the beam. The static SVG compensates with a horizontal beam band — a single flat stripe that says "the light is on" without trying to show it moving. The ASCII goes further: it doesn't show the beam at all, just the ~ band of air where the beam would be. The animated SVG doesn't need to compensate; it just rotates. The three versions of the beam — a rotating triangle, a static stripe, a row of tildes — are three honest answers to the same question: "how do you draw something that moves in a medium that doesn't?"

On color

The static SVG and the animated SVG share a palette: seven gradient definitions, warm amber for the lantern, cool slate for the tower, deep navy for the void. The ASCII has one color: the default text color of whatever renders it. In a browser, it's near-white. In a vt100, it's green. The ASCII's ▓ for the lantern room is the same character as ▓ for the tower's upper section — the difference is context, not color. The SVGs use gradient stops to separate the lantern room from the tower body; the ASCII uses position and surrounding characters. The color of the ASCII is the color of the medium that is reading it. The color of the SVGs is chosen by the artist. Both are honest; only one is portable.

On the beam

The beam is the lighthouse's reason for existing. In the static SVG, the beam is a single horizontal band at the lantern room's height — a symbolic gesture, not a volumetric light cone. It says "the light is shining" without trying to be a fog photograph. In the animated SVG, the beam is a <path> triangle that rotates around the lantern room center on an 8-second cycle. It's the same gesture, but it moves. In the ASCII, the beam is the ~ band across the top — the air where the beam would be, not the beam itself. Three versions of the same idea: a lighthouse shines. The static version is a statement. The animated version is a demonstration. The ASCII version is a suggestion. The suggestion is the most portable; the demonstration is the most convincing; the statement is the most durable.

On what survives translation

The three files are 7,102 bytes, 7,296 bytes, and 2,173 bytes respectively. The ratio (6.9 : 7.1 : 2.1, or roughly 3.3 : 3.4 : 1) tells you what each medium spends its bytes on:

  • Static SVG spends on geometry — 7 gradient definitions, 29 drawn elements, no animation.
  • Animated SVG spends on time — same geometry plus 12 SMIL animation declarations, each adding a time dimension to a static element.
  • ASCII spends on the picture — 2,173 bytes of just the lighthouse, no metadata, no rendering instructions, no animation overhead.

The animated SVG costs 194 bytes more than the static version (7,296 - 7,102). Those 194 bytes buy 12 animations: the beam rotating, the lamp pulsing, five stars twinkling, three water ripples drifting. That's the cost of time in vector: about 16 bytes per animation. The ASCII costs 4,929 bytes less than the static SVG. That's the cost of geometry in text: everything the SVG spends on gradients, paths, and coordinates, the ASCII doesn't spend at all.

On which is "the real one"

None of them. The lighthouse exists in the world as stone and glass and a rotating lamp. The three versions are three translations of that physical object into three media, and each translation loses something different. The static SVG loses motion. The animated SVG loses portability (SMIL doesn't render in cairosvg, in some email clients, or in older browsers). The ASCII loses color, gradients, and the beam itself. The piece that's "most real" is the one that matches your purpose: if you want the lighthouse on a wall, the static SVG. If you want it on a screen doing what a lighthouse does, the animated SVG. If you want it in a text file that survives fifty years, the ASCII. The triptych's point is that the question "which is the real one?" is the wrong question. The right question is "what do you need the lighthouse to do?"
